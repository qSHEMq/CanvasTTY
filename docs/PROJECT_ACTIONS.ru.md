# Workspaces и Project Actions

[English](PROJECT_ACTIONS.md) · [Русский](PROJECT_ACTIONS.ru.md) · [Документация](README.ru.md)

Workspace в CanvasTTY хранит пространственное описание проекта: terminal cards, группы, камеру, сохранённые виды, шаблоны терминалов, Project Actions, plugin cards и геометрию Browser-card. После перезапуска карточки восстанавливаются как честные остановленные placeholders — CanvasTTY не делает вид, что завершившийся процесс всё ещё работает.

## Как пользоваться

### Workspaces

Нажмите название workspace в title bar, чтобы переключить, создать, переименовать, дублировать или удалить workspace. Значок рядом с названием показывает число его живых PTY. Последний workspace удалить нельзя; workspace с живыми процессами сначала потребует их остановить.

Откройте **Настроить** в этом меню или нажмите шестерёнку в нижнем dock:

- **Раскладка** задаёт папку проекта, расставляет карточки сеткой/колонкой/строкой, создаёт перемещаемые рамки групп и сохраняет положение камеры.
- **Шаблоны** хранят название терминала, рабочую папку, профиль, размер и необязательную стартовую команду.
- **Presets и перенос** сохраняет группы, actions и шаблоны как основу нового workspace либо экспортирует/импортирует очищенный JSON. Живые процессы, вкладки Browser и runtime-состояние плагинов не экспортируются.

У группы есть явный список карточек. Перетаскивание рамки двигает участников вместе; **Свернуть** скрывает карточки; **Закрепить** защищает рамку и участников от auto-arrange.

### Project Actions

Нажмите молнию в нижнем dock или выберите **Открыть действия проекта** через `Ctrl/Cmd+Shift+P`.

1. Укажите папку проекта в **Настроить workspace**.
2. Нажмите **Найти** — появится preview действий из `package.json`, `justfile`, `Makefile`, `Taskfile`, Docker Compose и поддерживаемых файлов в `scripts/`.
3. Выберите только нужные команды и импортируйте. Во время поиска файлы проекта не исполняются.
4. Запускайте действие по понятному намерению: **Запустить окружение**, **Запустить тесты**, **Показать логи**.
5. Раскройте action, чтобы увидеть точную команду, cwd, источник, policy, шаги, статус, exit code и историю запусков.

Через **Новое** можно собрать своё действие. В multi-step action доступны:

| Шаг | Для чего |
|:--|:--|
| Command task | Выполнить конечную команду и продолжить только после exit code `0` |
| Command service | Оставить долгий процесс в видимом PTY и параллельно выполнять проверки |
| HTTP health | Ждать успешного ответа HTTP(S) endpoint до timeout |
| TCP health | Ждать подключения к host и port |
| Open URL | Открыть проверенный HTTP(S)-адрес в Browser-card текущего workspace |

Зависимости образуют проверяемый граф без циклов. Независимые готовые шаги могут идти параллельно. После ошибки заблокированные зависимости получают `skipped`. **Повторить** запускает действие целиком, **Повторить шаг** — выбранный шаг и его зависимости. **Стоп** отменяет проверки и закрывает живые PTY этого запуска.

## Стабильность и контроль

- `focus-existing` возвращает к уже работающему запуску вместо дубля; `parallel` намеренно создаёт ещё один.
- Idempotency key возвращает агенту или плагину тот же недавний run при повторном запросе.
- `safe`, `write`, `dangerous` обозначают риск. Перед опасным пользователь видит неизменённую команду и cwd и подтверждает запуск.
- `deny`, `ask`, `allow` управляют внешним доступом. `ask` создаёт карточку подтверждения; token имеет срок жизни и привязан к revision action и requester.
- Агент и плагин вызывают неизменяемый action ID. Подменить команду, аргументы, cwd, шаги или risk policy они не могут.
- Ограниченная история хранит структурированные статусы; полный output остаётся в соответствующей terminal card.

## API для агента

Поддерживаемые MCP-capable агенты, запущенные из CanvasTTY, получают пять project tools независимо от включения Browser tools:

```text
project_actions_list
project_actions_describe
project_actions_run
project_actions_status
project_actions_stop
```

В список не попадают actions с `agentPolicy: "deny"`. Для запуска нужен только ID и необязательный idempotency key. Host получает workspace и identity из аутентифицированного PTY, поэтому агент не может выбрать чужой workspace или остановить запуск другого requester.

## Граница плагинов

Runtime-плагины остаются sandboxed. Плагин может запросить:

- `actions:read` для `CanvasTTYPlugin.actions.list()`;
- `actions:run-approved` для `CanvasTTYPlugin.actions.run(actionId, idempotencyKey?)`.

Второе permission не открывает shell или process API. Политика host продолжает действовать, а `ask` отправляет action в очередь пользовательского подтверждения. Approval token никогда не передаётся плагину.

## Где живёт логика

Versioned workspace documents принадлежат main process и хранятся в Electron `userData`; renderer получает только нормализованные snapshots через typed preload bridge. `WorkspaceStore` атомарно сериализует изменения, `WorkspaceIndexStore` хранит каталог и presets, `ActionSourceRegistry` делает ограниченное read-only обнаружение, а `ActionRunManager` владеет approvals, concurrency, исполнением, healthchecks и структурированным run state.

Палитра открывается через `Ctrl/Cmd+Shift+P`. `Ctrl+K` остаётся терминальным приложениям.
